# lfrecruiting — прототип

Сайт Центру рекрутингу ЗСУ за брифом. Astro + TypeScript, без UI-фреймворка,
статична збірка. Фільтри — vanilla JS поверх даних, відрендерених у розмітку
на білді.

**Публічний перегляд:** https://igoraidev.github.io/recrutcenter/

## Команди

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # → dist/
npm run preview
npm run check    # astro check
```

Збірка керується двома змінними. Без них сайт збирається в корінь домену:

```bash
SITE=https://lfrecruiting.mil.gov.ua npm run build      # бойовий домен
SITE=https://igoraidev.github.io BASE_PATH=/recrutcenter npm run build   # GitHub Pages
```

## Що зібрано

**Головна** — усі десять блоків розділу 3 брифу:

| Блок | Файл |
| --- | --- |
| 1. Герой з фільтром і живим лічильником | `components/Hero.astro` |
| 2. Скільки платять | `components/PayBlock.astro` |
| 3. Популярні вакансії | `pages/index.astro` + `VacancyCard.astro` |
| 4. Три шляхи | `components/PathTiles.astro` |
| 5. Чому через центр | `components/WhyBlock.astro` |
| 6. Як це відбувається | `components/StepsBlock.astro` |
| 7. Відповіді на страхи (FAQPage) | `components/FaqBlock.astro` |
| 8. Історії переходів | `components/StoriesBlock.astro` |
| 9. Підрозділи | `components/UnitsGrid.astro` |
| 10. Представництва і контакти | `components/ContactsBlock.astro` |

**Сторінки**

- `/vacancies` — каталог із тими самими фільтрами, що й у героі
- `/vacancy/[slug]` — картка з `JobPosting`, хлібними крихтами, унікальними
  метатегами з поля `summary` і формою заявки
- `/profession/[group]` — хаб за професією: одна сильна сторінка замість
  двадцяти карток, які конкурують у видачі
- `/variant-b` — друга половина A/B першого екрана, закрита від індексації
- `/sitemap.xml`, `/robots.txt` — генеруються з даних, без зайвої залежності

### Що виконано з обмежень брифу

- Немає відео-прелоадера, автоплею до контенту, каруселей, рухомого рядка,
  дублювання шевронів у розмітці.
- `user-scalable=no` не використовується; `localStorage` не використовується —
  стан фільтрів живе в адресному рядку.
- Шрифти самохостяться, кирилиця вантажиться за `unicode-range`.
- Анімація одна — перерахунок лічильника; `prefers-reduced-motion` враховано.
- Фокус видимий скрізь, є skip-link, чипи мають `aria-pressed`, лічильник —
  `aria-live`.
- Без JS сторінки лишаються робочими: на головній рендеряться перші 9 карток,
  у каталозі — усі, форма героя переходить у каталог звичайним GET.
- У варіанті Б відео вмикається тільки на швидкій мережі й без
  `prefers-reduced-motion`; `preload="none"`, перший кадр — постер.

## Заглушки, які треба замінити

1. **Суми виплат** — `src/data/pay.json`. Потребують погодження командування
   (розділ 12, питання 1). Поки `"approved": false`, блок підписує дані як
   попередні. Не публікувати без підтвердження.
2. **Метрика часу відповіді** — `src/data/response-time.json`. Поки
   `"published": false`, блок показує позначку «демонстраційне значення».
   Обіцянка «відповідь за 24 години» без реального обліку заявок гірша за
   відсутність обіцянки.
3. **Адреси представництв** — `src/data/offices.json`. Поки `address: null`,
   блок пише «уточнюємо» замість вигаданої адреси військового об'єкта.
4. **Історії переходів** — `src/data/stories.json`. Поки жодного
   `published: true`, блок показує структуру й підписує це на сторінці.
5. **Вакансії** — `src/data/vacancies.json`, 20 записів за схемою з розділу 6.
   Пізніше — запит до MariaDB на білді. Поля `salaryFrom`, `salaryNote`,
   `region` у поточній базі відсутні; їх додавання і є основна робота по бекенду.
6. **Приймання заявок** — форма на картці вакансії веде на `/apply`, якого
   поки немає. Потрібен бекенд: автовідповідь кандидату, миттєве повідомлення
   рекрутеру, статус заявки.
7. **Шеврони, og-картинка, відео першого екрана** — згенеровані плейсхолдери
   в `public/`.

## Розгортання

**GitHub Pages** — автоматично при пуші: `.github/workflows/deploy.yml`
збирає сайт і публікує `dist` у гілку `gh-pages`.

**Власний сервер** — `Dockerfile` і `docker-compose.yaml`: збірка статики в
контейнері, роздача через nginx зі стисненням і кешем на хешовані ассети.
Node на сервері не потрібен. Домен задається змінною `SITE`.

## Модель даних

`src/data/types.ts` — тип `Vacancy` за розділом 6 брифу, без змін.

`src/data/taxonomy.ts` — родини спеціальностей для фільтра. `roleGroup` у
вакансії лишається професією, під яку робиться хаб `/profession/[group]`;
родини — це рівень подання, бо 17 професій у фільтрі нечитабельні.

## Наступні кроки

- Аналітика воронки — до того, як щось міняти в дизайні (принцип 9).
- Бекенд заявок і статус для кандидата.
- Сторінки `/about`, `/conditions`, `/contract-18-24`, `/transfer`, `/return`,
  `/quiz`, `/unit/[slug]` — на них уже є посилання.
- A/B першого екрана: варіант А проти варіанта Б. Метрика — не час на сайті,
  а частка тих, хто дійшов до відправки заявки.
