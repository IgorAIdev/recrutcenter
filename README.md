# lfrecruiting — прототип

Головна сторінка Центру рекрутингу ЗСУ за брифом. Astro + TypeScript, без
UI-фреймворка, статична збірка. Фільтри — vanilla JS поверх даних, відрендерених
у розмітку на білді.

## Команди

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # → dist/, кладеться на Apache без Node на сервері
npm run preview
npm run check    # astro check
```

## Що зібрано

Дизайн-система (розділ 5 брифу) і блоки 1–5 головної (розділ 3):

| Блок | Файл | Стан |
| --- | --- | --- |
| 1. Герой | `src/components/Hero.astro` | готово |
| 2. Скільки платять | `src/components/PayBlock.astro` | готово, суми на погодженні |
| 3. Популярні вакансії | `src/pages/index.astro` + `VacancyCard.astro` | готово |
| 4. Три шляхи | `src/components/PathTiles.astro` | готово, посилання на майбутні розділи |
| 5. Чому через центр | `src/components/WhyBlock.astro` | готово, метрика відповіді — заглушка |

Блоки 6–10 (кроки, FAQ, історії, підрозділи, контакти), каталог, картка вакансії
і сторінки-хаби за професією — не робились: за брифом їх беруть після погодження
головної.

### Що виконано з обмежень брифу

- Немає відео-прелоадера, автоплею, каруселей, рухомого рядка.
- `user-scalable=no` не використовується, масштабування доступне.
- `localStorage` не використовується; стан фільтрів живе в адресному рядку.
- Жодної залежності заради однієї функції: увесь клієнтський код — один файл
  `src/scripts/filters.ts`, він інлайниться в HTML і не додає окремого запиту.
- Шрифти самохостяться (`@fontsource`), кириличні підмножини вантажаться за
  `unicode-range`; латиниця й інші підмножини не вантажаться взагалі.
- Анімація одна — перерахунок лічильника; `prefers-reduced-motion` враховано.
- Фокус видимий скрізь, є skip-link, чипи мають `aria-pressed`, лічильник —
  `aria-live="polite"`.
- Без JS сторінка лишається робочою: показуються перші 9 карток, форма героя
  переходить у каталог звичайним GET-запитом.

## Заглушки, які треба замінити

1. **Суми виплат** — `src/data/pay.json`. Потребують погодження з командуванням
   (розділ 12 брифу, питання 1). Поки `"approved": false`, блок сам підписує дані
   як попередні. Не публікувати без підтвердження.
2. **Метрика часу відповіді** — `src/data/response-time.json`. Поки
   `"published": false`, блок показує позначку «демонстраційне значення».
   Обіцянка «відповідь за 24 години» без реального обліку заявок гірша за
   відсутність обіцянки — прибирати позначку тільки разом із під'єднанням обліку.
3. **Вакансії** — `src/data/vacancies.json`, 20 записів за схемою з розділу 6.
   Пізніше — запит до MariaDB на білді. Поля `salaryFrom`, `salaryNote`, `region`
   у поточній базі відсутні; їх додавання і є основна робота по бекенду.
4. **Шеврони підрозділів** — `public/patches/*.svg`, згенеровані плейсхолдери.
5. **og-картинка** — `public/og-default.svg`, тимчасова.

## Модель даних

`src/data/types.ts` — тип `Vacancy` за розділом 6 брифу, без змін.

`src/data/taxonomy.ts` — родини спеціальностей для фільтра. `roleGroup` у вакансії
лишається професією, під яку робиться сторінка-хаб `/profession/[group]`; родини —
це рівень подання, бо 17 професій у фільтрі нечитабельні.

## Наступні кроки

- Блоки 6–10 головної: кроки, FAQ з розміткою `FAQPage`, історії, підрозділи,
  контакти представництв.
- Каталог `/vacancies` з тими самими фільтрами (компоненти вже переносяться).
- Картка `/vacancy/[slug]` з `JobPosting`, хлібними крихтами, унікальними
  метатегами з поля `summary`.
- Sitemap і `robots.txt`.
- Аналітика воронки — до того, як щось міняти в дизайні.
